The `text.xml.hana` grammar covers every XML-based design-time artifact. It adds no HANA-specific tokens: it includes VS Code's built-in `text.xml` grammar, so highlighting is plain XML. Artifact structure (root elements, node types, attributes) is specified per artifact family in `docs/specs/artifacts/`, not here.

## 2. Lexical Tokens & Comments

> Source: research/refs/extracted/hana-cloud-database_SAP_HANA_Cloud,_SAP_HANA_Database_Deployment_Infrastructure_/008_pages_211_240.md (Pages 211–240: `.hdbanalyticprivilege`, `.hdbflowgraph` examples)
> Source: research/refs/extracted/hana-cloud-database_SAP_HANA_Cloud,_SAP_HANA_Database_Deployment_Infrastructure_/009_pages_241_270.md (Pages 241–270: `.hdbreptask`, `.hdbsearchruleset` examples)

Tokens follow XML 1.0. Scopes are those of the built-in `text.xml` grammar.

| Token Class | Pattern / Delimiter | TextMate Scope (`text.xml`) | Notes |
| :--- | :--- | :--- | :--- |
| XML declaration | `<?xml version="1.0" encoding="UTF-8"?>` | `meta.tag.preprocessor.xml` | First line of every printed example. Optional for the parser. |
| Processing instruction | `<?name ... ?>` | `meta.tag.preprocessor.xml` | No HANA artifact uses one besides the declaration. |
| Comment | `<!-- ... -->` | `comment.block.xml` | `--` inside a comment is not reported. |
| CDATA section | `<![CDATA[ ... ]]>` | `string.unquoted.cdata.xml` | Content is opaque (no tags, no entities). Used for SQLScript bodies of script-based calculation views. |
| Start / empty / end tag | `<name ...>`, `<name .../>`, `</name>` | `meta.tag.xml`, `entity.name.tag.xml` | Names may carry one namespace prefix (`Calculation:scenario`, `flowgraph:ContainerNode`). |
| Attribute name | `[A-Za-z0-9_:.-]+` | `entity.other.attribute-name.xml` | Namespace-qualified names are common: `xsi:type`, `xmi:id`, `xmlns:Calculation`. |
| Attribute value | `"..."` or `'...'` | `string.quoted.double.xml` / `string.quoted.single.xml` | No backslash escapes. A quote of the same kind is written as an entity. |
| Predefined entity | `&quot;` `&apos;` `&lt;` `&gt;` `&amp;` | `constant.character.entity.xml` | `.hdbreptask` quotes SQL identifiers as `&quot;IM_SERVICES&quot;.&quot;INPUT_PRIM_KEY&quot;`. |
| Character reference | `&#NN;` `&#xHH;` | `constant.character.entity.xml` | |
| Text content | anything up to the next `<` | (no scope) | Holds formulas, filter expressions, URIs (`<resourceUri>pkg::OBJ</resourceUri>`). |

**HANA value conventions** (plain attribute or text values; the grammar does not scope them):

| Convention | Example | Where |
| :--- | :--- | :--- |
| Repository object name `pkg::OBJECT` | `<modelUri>sap::calcview2</modelUri>` | `[HDI]` `resourceUri`, `modelUri`, root `id` |
| XSC repository path | `/pkg/calculationviews/CV_X` | `[XSC]` `resourceUri` |
| Node reference `#id` | `<input node="#Projection_1">` | calculation view inputs |
| Session placeholders | `defaultClient="$$client$$"`, `$$language$$` | view roots |
| Wildcards `%` / `_` | `<modelUri useWildCards="true">sap::calcview%</modelUri>` | `.hdbanalyticprivilege` |

## 3. Keywords by TextMate Scope

The grammar is a pure delegate:

```json
{ "name": "SAP HANA XML", "scopeName": "text.xml.hana", "patterns": [{ "include": "text.xml" }] }
```

| Scope class | `text.xml.hana` content |
| :--- | :--- |
| `keyword.control.xml` | none |
| `storage.type.xml` | none |
| `storage.modifier.xml` | none |
| `constant.language.xml` | none (enumerated attribute values such as `dataCategory="CUBE"` stay `string.quoted.*`) |
| `support.function.xml` | none (calculated-column functions inside `<formula>` stay unscoped text) |

The grammar test (`test/grammar.test.ts`) asserts that each language of §1 maps to `text.xml.hana`.

## 4. Embedded Language Injections

None. Embedded code is not highlighted:

| Embedded content | Element / attribute | Language | Status |
| :--- | :--- | :--- | :--- |
| Calculated column expression | `<calculatedViewAttribute><formula>` | Column engine expression or SQL expression | plain text |
| Filter expression | `<filter>` | Column engine expression or SQL expression | plain text |
| Script view body | `<definition>` in `Calculation:ScriptView` (often CDATA) | SQLScript | plain text / CDATA |
| SQL identifiers | `.hdbreptask` `RemoteObjectUniqueName` | SQL (entity-encoded quotes) | plain attribute value |

A future injection must keep the XML tokenizer in control of `<`, `&` and the closing quote, so an injection may only target CDATA content or text content of a known element.

## 5. Complete EBNF / BNF Productions

Well-formed XML subset accepted by the offline parser (`parseXmlTree` in `src/analyzer/xml-parser.ts`). The productions are XML 1.0 well-formedness with the restrictions listed below; no DTD, schema or namespace validation is performed.

```ebnf
document        ::= prolog element misc* ;
prolog          ::= [ xml_decl ] misc* ;
xml_decl        ::= "<?xml" { any_char - "?>" } "?>" ;
misc            ::= comment | pi | doctype | whitespace ;
doctype         ::= "<!" { any_char | quoted | "[" { any_char } "]" } ">" ;   (* skipped, not validated *)

element         ::= empty_tag
                  | start_tag content end_tag ;          (* end_tag name = start_tag name *)
empty_tag       ::= "<" name { whitespace attribute } [ whitespace ] "/>" ;
start_tag       ::= "<" name { whitespace attribute } [ whitespace ] ">" ;
end_tag         ::= "</" name [ whitespace ] ">" ;

content         ::= { char_data | element | reference | cdata | comment | pi } ;
attribute       ::= attr_name [ whitespace ] "=" [ whitespace ] attr_value ;
attr_value      ::= '"' { any_char - '"' } '"'
                  | "'" { any_char - "'" } "'" ;
reference       ::= "&" ( "quot" | "apos" | "lt" | "gt" | "amp" ) ";"
                  | "&#" digit { digit } ";"
                  | "&#x" hex_digit { hex_digit } ";" ;

comment         ::= "<!--" { any_char - "-->" } "-->" ;
cdata           ::= "<![CDATA[" { any_char - "]]>" } "]]>" ;
pi              ::= "<?" name { any_char - "?>" } "?>" ;

name            ::= [ prefix ":" ] local_name ;
attr_name       ::= ( letter | digit | "_" | ":" | "-" | "." ) { letter | digit | "_" | ":" | "-" | "." } ;
char_data       ::= { any_char - ( "<" | "&" ) } ;
```

**Well-formedness errors.** Rule IDs for the languages of §1 (`docs/specs/diagnostics/syntax-rules.md`). Calculation views report every row as `HANA-LINT-101` instead.

| Condition | Rule | Message | Span |
| :--- | :--- | :--- | :--- |
| `<!--` without `-->` | `HANA-SYN-002` | `Unterminated XML comment.` | the `<!--` opener |
| `<![CDATA[` without `]]>` | `HANA-SYN-001` | `Unterminated CDATA section.` | the `<![CDATA[` opener |
| Attribute value without its closing quote | `HANA-SYN-001` | `Unterminated attribute value in '<tag>'.` | opening quote to the end of its line |
| `<?` without `?>` | `HANA-SYN-003` | `Unterminated XML processing instruction.` | the `<?` opener |
| `<!` declaration without `>` | `HANA-SYN-003` | `Unterminated XML declaration.` | the `<!` opener |
| `<name` without `>` | `HANA-SYN-003` | `Unterminated opening tag '<name'.` | `<name` |
| `</name` without `>` | `HANA-SYN-003` | `Unterminated closing tag '</name'.` | `</name` |
| `</b>` while `<a>` is open | `HANA-SYN-003` | `Mismatched closing tag '</b>' (expected '</a>').` | the end tag |
| `</a>` with nothing open | `HANA-SYN-003` | `Unexpected closing tag '</a>'.` | the end tag |
| Element still open at end of file | `HANA-SYN-003` | `Unclosed XML element '<a>'.` | the start tag |
| Attribute without `=`, unquoted value, or stray character in a tag | `HANA-SYN-012` | `Expected '=' after attribute 'a'.` / `Expected quoted value for attribute 'a'.` / `Unexpected character 'c' inside element attributes.` | the attribute name / the character |

**Recovery** (no cascading errors):

- A `<` inside a tag or an attribute value ends it, because XML 1.0 never allows `<` there. Parsing resumes at the `<`. The broken element stays in the tree, and closes silently at its own end tag or at its parent's end tag, because it may have been an empty element.
- A mismatched end tag closes its matching ancestor, if there is one.
- After an unterminated comment, CDATA section, PI, declaration or attribute value that reaches the end of the file, the elements still open are not reported again.

**Not checked** (accepted silently): DTD content (`<!DOCTYPE>` is skipped), undefined entity names (`&nbsp;`), a bare `&` in text or values, a `<` in text content, duplicate attributes, multiple root elements, text before the root, unbound namespace prefixes, root element names.

--- | :--- | :--- |
| `<!--` without `-->` | `Unterminated XML comment` | the `<!--` opener |
| `<![CDATA[` without `]]>` | `Unterminated CDATA section` | the `<![CDATA[` opener |
| `<?` without `?>` | `Unterminated XML processing instruction` | the `<?` opener |
| `<name` without `>` (quotes respected) | `Unterminated opening XML tag` | the first 20 characters from `<` |
| `</name` without `>` | `Unterminated closing tag` | the first 4 characters from `</` |
| Attribute without `=`, value not quoted, value quote not closed, or stray character in the tag | `Expected '=' after attribute '<a>'` / `Expected quoted value for attribute '<a>'` / `Unterminated quote in attribute '<a>'` / `Unexpected character '<c>' inside element attributes` | the whole tag |
| `</b>` while `<a>` is open | `Mismatched closing tag '</b>' (expected '</a>')` | the end tag |
| `</a>` with nothing open | `Unexpected closing tag '</a>'` | the end tag |
| Element still open at end of file | `Unclosed XML element '<a>'` | the start tag |

**Not checked** (accepted silently): `<!DOCTYPE>` declarations, undefined entity names (`&nbsp;`), a bare `&` or `<` inside an attribute value, duplicate attributes, multiple root elements, text before the root, unbound namespace prefixes.

Diagnostics: `.calculationview` / `.hdbcalculationview` report these errors as `HANA-LINT-101` (`artifacts/calculationview-schema.md` §5). Syntax checks for the other languages of §1 are tracked in #102 and specified in `docs/specs/diagnostics/syntax-rules.md`.

## 6. Canonical Formatting Rules (Phase 2)

**Not formatted.** No language of §1 is in `ALL_FORMATTER_LANGUAGES` (`src/formatter/dispatch.ts`), so the extension registers no document formatter for them, and VS Code falls back to any XML formatter the user installed.

- **Indentation:** none. These files are written by graphical modelers (SAP HANA Studio, SAP Web IDE, SAP Business Application Studio), which own the layout. Reformatting would produce large diffs on every save in the modeler.
- **Line breaks / separators:** none.
- **Termination:** not applicable (no statements, no semicolons).
- **Safety (if a formatter is ever added):** it must keep attribute order, attribute quote style, entity spelling (`&quot;` vs `"` in `'...'` values), CDATA sections and comments byte for byte, and must never re-indent text content (`<formula>`, `<definition>`), where whitespace can be significant.
